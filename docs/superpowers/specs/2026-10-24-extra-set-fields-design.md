# Дополнительные поля подхода: RIR, RPE и вес по желанию

Дата: 2026-10-24. Статус: согласовано с владельцем в чате. Продолжает
`2026-10-24-quick-entry-design.md`.

## Зачем

Сейчас RPE включается одним переключателем в настройках сразу для всех упражнений, а RIR (сколько
повторов осталось в запасе) и вес у упражнений «со своим весом» записать некуда. Владелец хочет
включать такие поля точечно — на конкретной карточке, когда они нужны, — и по умолчанию ничего
лишнего в истории не видеть: ни нулей, ни прочерков.

## Как это выглядит для пользователя

- В заголовке карточки упражнения на экране активной тренировки появляется кнопка **«+»** (первая
  среди иконок справа от названия, только не в режиме «только чтение»). Она открывает шторку
  **«Дополнительные поля»** со списком переключателей:
  - **Вес** — только у упражнений без поля веса (`bodyweight_reps`, `reps_only`, `duration`,
    `distance_duration`); подпись «Вес, кг» / «Вес, lb» по единице из настроек.
  - **RIR** — повторы в запасе, целое число 0–10.
  - **RPE** — как сейчас, 1–10 с половинками.
  Ниже отдельной строкой — переключатель **«Запоминать для этого упражнения»**: пока он включён,
  текущий набор полей сохраняется у самого упражнения, и в следующих тренировках карточка этого
  упражнения приходит сразу с этими колонками. Выключили — у упражнения запоминание стирается, но на
  текущей карточке поля остаются.
- Включённое поле добавляет колонку в таблицу подходов карточки (после основных значений, перед
  галочкой: … → RIR → RPE). Порядок колонок: №, прошлый раз, вес, повторы/время/дистанция, RIR,
  RPE, галочка. Подсказка-плейсхолдер берётся из прошлого выполнения, как у остальных полей.
- Выключение поля прячет колонку, но введённые значения не стираются (вдруг включат обратно);
  в базу они всё равно сохранятся — см. «Данные».
- **История** (экран прошлой тренировки): значение показывается только если оно есть:
  `100 кг × 8 · RIR 1 · @8,5`; вес у подтягиваний — `+10 кг × 8`. Пустые значения не рисуются
  никак. При редактировании прошлой тренировки карточка открывается с теми полями, которые были
  включены при записи.
- **Итоги** («Сегодня сделано») и предпросмотр быстрой записи: повторы с RIR пишутся как `9(1)`, то
  есть в той же записи, что принимает быстрый ввод. RPE в итогах не показывается. Дополнительный вес
  показывается в колонке веса: `10 кг × 8 / 8` — для этого `groupSets` группирует по весу любые
  подходы с весом, а не только у типов с полем веса.
- **Вкладка «История» на экране упражнения** показывает подходы тем же форматом, что история
  тренировки: `100 кг × 8 · RIR 1 · @8,5`, `+10 кг × 8`. Формат живёт в одной функции
  `formatSetLineWithExtras` в `src/features/workout/format.ts`.
- **Старые тренировки с RPE** (записаны до этой версии, `extra_fields = []`): при редактировании
  карточка включает поля, у которых в подходах есть значения (`extraFields ∪ {поля с непустыми
  значениями}` в `workoutToActiveWorkout`), иначе старые RPE стали бы невидимыми.
- **Ширина колонок**: колонки RIR и RPE уже основных (`flex: 0.75`), «прошлый раз» без изменений.
- **Настройки**: переключатель «Показывать RPE» удаляется вместе со своей строкой перевода.

## Быстрая запись

- `9(1)` — 9 повторов, RIR 1. Скобки сразу после числа повторов или через пробел: `9(1)`, `9 (1)`.
  Суффикс типа подхода и RIR — в любом порядке: `8(1)о` и `8о(1)`.
- `70х9(1)/8(1)/8(0)`, `Подтягивания 12(2)/10(1)`, `70кг 3 по 8(2)` — всё допустимо.
- Скобки без числа внутри или с нецелым / отрицательным числом — ошибка разбора «Не понял: «…»».
- Если в строке есть RIR, у карточки включается поле RIR. Если указан вес у упражнения без поля веса
  (`Подтягивания +10кг х 8`), включается поле «Вес». Это делает `commitQuickEntry`, который знает
  тип упражнения; стор получает список полей в `QuickEntryCommit.extraFields`.
- Предпросмотр показывает RIR в скобках: «Приседания со штангой · 70 кг × 9(1) / 8(1) / 8(0)».

## Данные

- `sets.rir` — новая колонка `integer`, nullable. `SetValues.rir: number | null`; `EMPTY_SET_VALUES`,
  `previous`, экспорт CSV (колонка `rir` после `rpe`), импорт бэкапа (старые бэкапы без `rir`
  импортируются как `null`).
- `workout_exercises.extra_fields` — `text` в режиме json, `ExtraField[]`, по умолчанию `[]`.
  Сохраняется при `saveWorkout`, читается в `getWorkout` и превращается в `ActiveExercise.extraFields`
  в `workoutToActiveWorkout` (`src/db/repo/workouts.ts`).
- `exercises.remembered_extra_fields` — `text` json, `ExtraField[]`, по умолчанию `[]`. Это и есть
  «запоминание»: переключатель в шторке включён ⇔ список непустой. Пока он включён, каждое изменение
  полей на карточке пишет тот же список в упражнение (`updateExercise`). При добавлении упражнения в
  тренировку (`addExercises`, `startFromRoutine`, `replaceExercise`, быстрая запись) карточка получает
  `extraFields = rememberedExtraFields` этого упражнения **плюс «Вес»**, если у упражнения без поля
  веса вес уже есть в прошлом выполнении или в запланированных подходах программы
  (`initialExtraFields`): иначе галочка подставила бы вес из прошлого раза в невидимую колонку. RIR и
  RPE из прошлого раза сами не включаются.
- `ActiveExercise.extraFields: ExtraField[]`. У активной тренировки, сохранённой прошлой версией
  приложения в kv-хранилище, поля нет — читать через `?? []` в одном месте (в `persist`-опции
  `merge`/`migrate` стора), чтобы остальной код полагался на массив.
- `ExtraField = 'weight' | 'rir' | 'rpe'` живёт в `src/domain/types.ts`.
- Миграция: `npm run db:generate` после правки `schema.ts`; новый файл `drizzle/0001_*.sql` и
  обновлённые `migrations.js` / `meta`. Таблицы `routine_sets` и `routine_exercises` не меняются:
  программы RIR не планируют.
- Рекорды и статистика RIR/RPE не учитывают. Рекорды у `bodyweight_reps` считаются только по
  повторам (`recordTypesForExercise`), дополнительный вес их не меняет. Понятие «объём» из
  интерфейса удалено отдельной задачей (см. план, Task 0).
- Плейсхолдеры RIR и RPE — из прошлого выполнения (для RPE это новое поведение: раньше плейсхолдер
  был пустым).

## Не делаем сейчас

- RIR и RPE в редакторе программ.
- Графики и рекорды по RIR/RPE.
- Автоматический пересчёт RPE ↔ RIR.

## Что будет считаться провалом

- В истории или итогах появляются «RIR —», «0» или пустые колонки у упражнений, где поля не включали.
- Старая активная тренировка (без `extraFields` в хранилище) падает после обновления.
- Миграция не применяется на телефоне с уже существующей базой.

## Решения, принятые мной

- RPE остаётся отдельным полем, а не заменяется RIR: у владельца есть прошлые данные с RPE.
- Запоминание — список полей у упражнения; переключатель «включён» значит «список непустой».
- Значения выключенных полей не стираются и попадают в базу: иначе случайное выключение теряло бы
  введённое; в истории их видно только если они есть, так что лишнего шума нет.
- Иконка кнопки — `Plus` из lucide, в том же стиле, что иконки книги и заметки.
