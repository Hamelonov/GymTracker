# Быстрая запись подходов текстом

Дата: 2026-10-24. Статус: согласовано с владельцем в чате.

## Зачем

Главная функция, ради которой приложение создавалось. В зале, сразу после сделанного подхода,
пользователь печатает одну строку вроде `Присед со штангой 70кг х 7/6/5` — и приложение само
находит упражнение в списке, добавляет карточку (или дописывает подходы в существующую) и заполняет
вес, повторы и тип подхода. Так записать подход быстрее, чем искать упражнение в списке и заполнять
ячейки по одной.

## Как это выглядит для пользователя

- На экране активной тренировки вместо одной широкой кнопки «Добавить упражнение» — **две кнопки
  в один ряд, без текста, только иконки**. Левая открывает привычный список упражнений, правая —
  поле быстрого ввода. Обе одинаковой высоты, делят ширину ряда пополам; стиль как у текущей кнопки
  (primary, когда упражнений ещё нет, иначе secondary).
- Поле быстрого ввода — нижняя шторка (`Sheet` из `src/ui`) с многострочным полем, подсказкой-примером
  и кнопкой «Добавить». Клавиатура открывается сразу.
- Пока пользователь печатает, под полем живёт **предпросмотр**: для каждой строки — распознанное
  упражнение и подходы в привычном виде, например `Приседания со штангой · 70 кг × 7 / 6 / 5`.
  Если название не найдено, предпросмотр говорит «Новое упражнение: Присед со штаного». Если строку
  не удалось разобрать, под ней короткая подсказка, что не так, и кнопка «Добавить» неактивна, пока
  все строки не разберутся.
- По нажатию «Добавить» шторка закрывается, подходы появляются в карточках уже **выполненными**
  (с галочкой и временем выполнения), как если бы галочку нажали вручную. После добавления запускается
  таймер отдыха по тем же правилам, что и при ручной галочке (режим новой тренировки, включённый
  автозапуск, время отдыха упражнения или по умолчанию). Если добавили несколько упражнений, таймер
  запускается один раз — для последнего.
- Показывается тост «Добавлено: Приседания со штангой · 3 подхода» (для нескольких упражнений —
  «Добавлено: 2 упражнения · 5 подходов»).
- Строка — команда, а не документ. Введённый текст нигде не хранится и не редактируется. Ошибки
  исправляются обычными средствами карточки (удалить подход, удалить упражнение) и повторным вводом.

## Грамматика строки

Одна строка = одно упражнение. Несколько упражнений — каждое с новой строки.

```
<название> [<вес>] [х] <подходы>
```

### Название

Всё от начала строки до первого числа. Название может содержать цифры внутри слов (`T-bar`) — числом
считается только отдельный токен; число с приклеенной единицей (`21s`) уже считается значением.

### Вес

- `70`, `70кг`, `70 кг`, `70kg`, `70lb`, `70 фунтов`, `72,5` или `72.5`. Запятая читается как дробь
  только у веса в начале группы (`72,5кг х 5`, `Присед 72,5 х 5`); после `/`, `х` или числа запятая
  разделяет группы: `70х7/6,80х5` — это 70×7, 70×6, 80×5.
- Повторы — только целое число больше нуля; `8.5` и `0` дают ошибку разбора.
- Без единицы — единица веса из настроек (кг или lb). С единицей — переводится в кг при сохранении.
- `+10кг` — дополнительный вес для упражнений со своим весом (тип `weighted_bodyweight`): хранится как
  `weightKg = 10`. `-20кг` — помощь (тип `assisted_bodyweight`). Если у упражнения тип `bodyweight_reps`,
  а вес указан, вес всё равно записывается в `weightKg` — поле есть в модели, а тип упражнения не меняем.
- Разделитель между весом и повторами: `х` (русская), `x`, `X`, `×`, `*`. Пробелы вокруг не важны.
  Если разделителя нет, а есть два числа (`70 7`) — первое вес, второе повторы.

### Подходы

- `7/6/5` — три подхода по одному весу. Разделитель подходов — `/` (также `\`, `|`).
- `70х7/6, 80х5` — группы с разными весами через `,` или `;`. Вес группы наследуется, пока не
  появится новый: `70х7/6, 5` → третий подход тоже 70 кг.
- `3 по 7` или `3по7` — три подхода по 7 повторов. `70кг 3 по 7` → 70×7, 70×7, 70×7.
  Также `3x7` **не** поддерживается как «3 по 7»: `x` всегда разделяет вес и повторы.
- Только повторы без веса: `Подтягивания 12/10/8`. Если у найденного упражнения есть поле веса, а
  вес не указан, `weightKg` остаётся `null` (как пустая ячейка).

### Тип подхода

Буква сразу после числа повторов, без пробела:

| Суффикс | Тип |
| --- | --- |
| `р`, `w` | `warmup` (разминка) |
| `о`, `f` | `failure` (до отказа) |
| `д`, `d` | `drop` (дроп-сет) |

`70х7р/7/5о` → разминка 7, обычный 7, отказ 5.

### Время и дистанция

- Время: `1:00`, `0:45`, `45с`, `45s`, `45 сек`, `20 мин`, `20 min`, `1ч`, `1h`, `1ч20м`.
- Дистанция: `5км`, `5 km`, `500м`, `500 m`, `3 мили`, `3mi`.
- Одиночная буква `м`/`m` после числа — всегда метры, кроме записи после часов (`1ч20м`), где это минуты.
  Для минут писать `мин`/`min`.
- Голое число у упражнения на дистанцию и время (`Бег 5`) — дистанция в единицах из настроек.
- Для упражнений типа `duration`: `Планка 1:00/0:45` — два подхода по времени.
- Для `distance_duration`: `Бег 5км 25:00` — один подход; `Бег 1км 5:00 / 1км 4:50` — два.
  Порядок «дистанция, потом время» или «время, потом дистанция» — любой, определяется по единицам.
- Если найденное упражнение на повторы, а в строке время — строка считается ошибкой с подсказкой
  «У этого упражнения считаются повторы».
- Если упражнение на время, а в строке голые числа (`Планка 60`, `Планка 3 по 60`) — числа считаются
  секундами.

### Что не является ошибкой

- Строка только с названием (`Присед`) — добавляет карточку с одним пустым подходом, как из списка.
  Галочка не ставится, таймер не запускается.
- Лишние пробелы, регистр, `ё`/`е`, запятая вместо точки в дробях.

### Ошибки разбора

- Пустая строка пропускается.
- Строка без названия (`70х7`) — «Напишите название упражнения».
- Непонятный хвост после подходов — «Не понял: «…»» с проблемным фрагментом.

## Распознавание названия

Чистая функция `matchExerciseName(text, candidates)` в `src/domain/quickEntry/` без зависимостей
и без сети.

1. **Нормализация**: нижний регистр, `ё → е`, латинская/кириллическая путаница не трогается,
   знаки препинания и скобки → пробелы, токенизация по пробелам.
2. **Стемминг**: грубое отсечение русских окончаний (`-ания`, `-ение`, `-ами`, `-ой`, `-ом`, `-ах`,
   `-ы`, `-и`, `-а`, `-я`, `-е`, `-ий`, `-ый`, `-ая` и т. п.) до основы не короче 3 символов; для
   английского — `-s`, `-es`, `-ing`. Это даёт «присед» ≈ «приседания», «штангой» ≈ «штанга».
3. **Стоп-слова**: предлоги и союзы (`с`, `со`, `на`, `в`, `и`, `из`, `the`, `with`, `on`) не
   участвуют в сравнении.
4. **Счёт**: для каждого кандидата сравниваем множества стемов запроса и названия. Пара стемов
   считается совпавшей, если один стем — префикс другого (не короче 4 символов), либо при одинаковой
   первой букве расстояние Дамерау–Левенштейна ≤ 1 для слов до 5 букв и ≤ 2 для более длинных
   (первая буква обязана совпадать, иначе «трицепс» находил «бицепс»). Кандидат подходит, если
   **первый стем запроса** (само движение: «присед», «жим», «тяга») нашёлся в названии и при этом
   либо совпало ≥ 60 % стемов запроса, либо все стемы названия нашлись в запросе («Подтягивания»
   для запроса «подтягивания широким хватом», которого в библиотеке нет).
5. **Порядок предпочтения** среди подошедших: название без лишних слов (все его стемы есть в
   запросе) → больше доля совпавших стемов запроса → упражнение уже в тренировке → то, что
   пользователь делал чаще (`getExerciseUsage`) → первый стем названия совпал с первым стемом запроса
   → встроенное перед пользовательским → порядок в библиотеке (в каждой группе первым идёт самое
   ходовое) → более короткое совпавшее название. Поиск идёт сначала среди упражнений текущей
   тренировки, затем по всей неархивной библиотеке по русскому и английскому названиям. Ошибаться
   в сторону базового упражнения безопаснее, чем в сторону чужой вариации, поэтому «название без
   лишних слов» стоит первым. Предпросмотр всегда показывает выбранное упражнение.
6. **Нет совпадения** — создаётся пользовательское упражнение (`createExercise`, `isCustom: true`)
   с названием ровно как написано (обрезанные пробелы, первая буква заглавная), оба языка получают
   одно имя. Тип выводится из строки: есть вес или `х` → `weight_reps`; только повторы →
   `bodyweight_reps`; только время → `duration`; дистанция → `distance_duration`; одно название
   без чисел → `weight_reps`. Вес для `assisted_bodyweight` хранится положительным числом (минус
   рисует карточка), поэтому `-20кг` → `weightKg = 20`. Группа мышц —
   по ключевым словам в названии, если угадывается (`присед`, `жим лёжа`, `тяга`, `бицепс`…), иначе
   `full_body`. Инвентарь — по словам `штанг` → barbell, `гантел` → dumbbell, `гир` → kettlebell,
   `тренаж` → machine, `блок` → cable, `резин` → band, иначе `other` (для `bodyweight_reps` —
   `bodyweight`). В следующий раз упражнение уже находится как обычное.
7. Несколько строк с одним и тем же упражнением в одном вводе объединяются в одну карточку.

Подбор поведения проверяется юнит-тестами с набором типичных опечаток владельца:
«присед со штаного», «присидания с штонгой», «жым лежа», «подтягивание», «тяга верхнего блока к
груди» и т. п.

## Куда попадают данные

- Новый метод стора `addParsedEntries(entries)` в `src/store/activeWorkout.ts` (или отдельный
  модуль рядом, если стор перерастёт 250 строк): для каждой записи ищет упражнение в тренировке по
  `exerciseId`; если нет — создаёт карточку как `addExercises`, но **без** пустых подходов из прошлого
  выполнения. Затем подходы из строки **занимают по порядку первые незавершённые подходы карточки**
  (запланированные из программы или пустые): их значения и тип заменяются, ставится `completed: true`,
  `completedAt: Date.now()`. Уже завершённые подходы не трогаются. Когда незавершённые кончились —
  новые подходы дописываются в конец с `previous` из последнего выполнения по индексу подхода (как
  делает `makeSet`). Значения из `previous` в пустые поля **не** подставляются: записывается ровно
  то, что напечатано. Возвращает id упражнений и число добавленных подходов для тоста и таймера.
- Экран `active.tsx` вызывает его из обработчика шторки и запускает таймер той же логикой, что
  `toggleSet` (вынести общий кусок в функцию `startRestAfterCompletedSet`).
- Сохранение в базу, рекорды и статистика не меняются: подходы попадают в `saveWorkout` обычным
  путём.

## Структура кода

```
src/domain/quickEntry/
  tokenize.ts          — токены: слово, число, разделитель, единица
  parseLine.ts         — строка → { name, sets[] } или ошибка
  parseEntry.ts        — многострочный текст → массив результатов
  matchExercise.ts     — нормализация, стемминг, оценка, выбор кандидата
  inferExercise.ts     — тип, группа мышц, инвентарь для нового упражнения
  __tests__/           — тесты парсера и распознавания
src/features/workout/quickEntry/
  QuickEntrySheet.tsx  — шторка: поле, предпросмотр, кнопка
  QuickEntryPreview.tsx — строки предпросмотра
  useQuickEntry.ts     — связывает текст, разбор и список кандидатов (memo)
  AddExerciseButtons.tsx — ряд из двух кнопок
```

## Не делаем сейчас

- Редактирование уже введённой строки и хранение «исходного текста» подхода.
- Запоминание псевдонимов «опечатка → упражнение» между тренировками.
- Ручной выбор упражнения из предпросмотра, если распознано неверно (пока — переформулировать).
- Быстрый ввод в редакторе программ и при редактировании прошлой тренировки (`session.mode === 'edit'`
  показывает обе кнопки, но таймер не запускает — как сейчас).
- Голосовой ввод.

## Что будет считаться провалом

- Разбор или подбор заметно тормозит набор текста (предпросмотр должен обновляться синхронно на
  каждом символе; библиотека ~120 упражнений, стемы кандидатов считаются один раз и кэшируются).
- Уверенно подставляется не то упражнение без возможности это увидеть до отправки.
- Приходится дожимать галочки руками после ввода.

## Решения, принятые мной

- Иконки кнопок: `ListPlus` для списка и `MessageSquarePlus` для текста (обе с плюсом, но различимы).
- Шторка закрывается после добавления; для следующей записи — снова нажать кнопку.
- Для разных весов разделитель группы — запятая/точка с запятой; «3 по 7» — единственная форма
  умножения подходов.
- Суффиксы типа подхода — одиночные буквы `р/о/д` и `w/f/d`.
- Новое упражнение создаётся сразу в библиотеке, без вопроса. Удалить его можно из библиотеки.
- У `Button` обязателен `title`; для кнопок с одной иконкой компонент расширяется (`title`
  необязателен, когда есть `icon`), а не передаётся пустая строка.
